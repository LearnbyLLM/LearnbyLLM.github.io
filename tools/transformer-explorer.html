Transformer Explorer

Step inside the architecture behind modern language models — from raw text to next-token probabilities, one stage at a time.

The numbers in this tool are illustrative, computed with toy rules in your browser — not weights from a real trained model. The mechanisms are what real transformers do; the specific values are not.

Text becomes tokens

A transformer never sees letters or words directly. The first step is a tokenizer that chops text into pieces from a fixed vocabulary — often whole common words, but rarer words get split into subword chunks. Each piece maps to an integer ID.

Why subwords?

With ~50,000–200,000 subword pieces, a model can spell out any text — including words it has never seen — while keeping common words as single efficient tokens. Try typing a made-up word like flurbognathic above and see it shatter into pieces.

Tokens become vectors

Each token ID looks up a row in a giant embedding table: a list of numbers (real models use 1,000–20,000 dimensions; we show 16). These numbers are learned during training so that tokens used in similar ways end up with similar vectors.

Attention: tokens look at each other

This is the transformer's superpower. For every token, attention computes a set of weights over all previous tokens: "how relevant is each earlier token to understanding me?" The token then blends in information from the tokens it attends to.

One layer is simple. Stack dozens.

A transformer layer is just two steps: attention (tokens exchange information) followed by a small neural network called an MLP applied to each token separately (each token "thinks about" what it just gathered). That block is repeated dozens of times:

Input tokens"The robot was learning…"
↓
Embeddings + positionseach token → vector, plus "where am I in the sentence"
↓
Attentiontokens look at earlier tokens and blend information
↓
MLPeach token processes what it gathered
↻ repeat this block 30–100+ times
Output layerfinal vector → score for every token in the vocabulary
↓
Probabilitiessoftmax turns scores into a probability for each next token

Why does depth matter?

Early layers tend to capture grammar and local structure; middle layers build up facts and relationships; late layers shape the final prediction. Each layer refines every token's vector using context gathered by the layer before — so by the top of the stack, the vector for bank in "river bank" is very different from bank in "bank account".

It all ends in one humble task

After all that machinery, the model outputs a probability for every token in its vocabulary being next. That's it. Text generation is just: predict, pick one, append, repeat.

What temperature does

Low temperature (←) sharpens the distribution — the model almost always picks the top choice. Predictable, sometimes repetitive. High temperature (→) flattens it — unlikely tokens get a real chance. Creative, sometimes incoherent.
